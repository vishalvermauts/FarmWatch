## 2025-03-09 - [Critical] Prevent GEE Token Exfiltration via SSRF
**Vulnerability:** Server-Side Request Forgery (SSRF) allowing Google Earth Engine (GEE) access token exfiltration. The `/api/satellite/tile` endpoint accepts a `mapName` query parameter which, if starting with 'http', was used unmodified to construct the final `geeTileUrl`. The server then made a `fetch` to this attacker-controlled URL with the `Authorization: Bearer <GEE_TOKEN>` header attached.
**Learning:** Naive concatenation of user-provided input (`mapName`) into outbound server request URLs, specifically when those requests attach sensitive credentials, creates a high-impact exfiltration vector. Even if the intent is to support absolute URLs from an upstream API, blind trust allows the token to be sent to any domain.
**Prevention:** Always validate and whitelist the origin of outbound requests before attaching sensitive headers. Ensure constructed URLs are strictly bounded to expected, trusted endpoints (e.g., `https://earthengine.googleapis.com/`).
